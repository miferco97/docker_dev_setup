# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This repo manages Docker-based development environments for robotics research projects (mostly ROS2). Each project gets its own container with isolated dependencies while source code lives on the host for persistence. The `docker-env` CLI orchestrates building, starting, and attaching to containers.

## Key Commands

```bash
# Setup: add to ~/.bashrc
source ~/docker_dev_setup/.bin/autocomplete_docker_dev_setup

# CLI usage
docker-env list                        # List all projects (running ones in yellow)
docker-env list -r                     # Only running projects
docker-env build <project> [-v] [--no-cache]  # Build project image
docker-env up <project>                # Generate devenv compose, start, and attach
docker-env down <project>              # Stop project container
docker-env restart <project>           # Restart container
docker-env setup <project>             # Build and start (no devenv overlay)

# Inside containers - ROS2 build
rosbuild [package_name] [-v] [-d]      # colcon build wrapper (from complementary_bashrc)
```

## Architecture

### Incremental Build Strategy

The core mechanism is `extend_docker_compose.py`, which merges a project's `docker-compose.yml` with the shared `devenv_compose.yml` to produce a two-service compose file:

1. **`<project>_build`** — builds the project base image (tagged `:base`), runs `true`
2. **`<project>_dev`** — layers the devenv image on top (tagged `:dev`) using `devenv.Dockerfile`, mounts all dev volumes (nvim, tmux, claude, SSH, git configs)

The generated file goes to `<project>/.devenv/docker-compose-devenv.yml`.

The devenv compose template supports two special variables resolved by `extend_docker_compose.py`:
- `$PROJECT_DIR` — absolute path to the project directory
- `$PROJECT_NAME` — basename of the project directory

These are replaced in both volume paths and environment values during the merge.

### Dev Environment Layer (`.dev_env_image/devenv.Dockerfile`)

Multi-stage Dockerfile applied on top of any project base image:
- Stage 1: builds Neovim from source
- Stage 2: creates non-root user matching host UID/GID, installs tmux, Node.js 20, Claude Code (native installer), linters (clang-format, clang-tidy, cpplint, cmakelint), ripgrep

### Claude Code Mount Strategy

Each container gets Claude Code with isolated per-project data but shared auth and usage tracking:

| Mount | Source | Mode | Purpose |
|---|---|---|---|
| `~/.claude/` | `<project>/.claude_local/` | rw | Per-project memory, settings, cache |
| `~/.claude.json` | Host `~/.claude.json` | rw | Auth/app state |
| `~/.claude/.credentials.json` | Host | rw | OAuth token |
| `~/.claude/settings.json` | Host | rw | Global permissions and model prefs |
| `~/.claude/projects/` | Host `~/.claude/projects/dev-env-<name>/` | rw | Session JSONLs namespaced per project |

The `projects/` mount ensures a GNOME Shell usage monitor can track token costs across all containers from `~/.claude/projects/dev-env-*/`.

### Project Structure Convention

Each project directory contains:
- `Dockerfile` — project-specific image
- `docker-compose.yml` — single service with build/run config
- `entrypoint.sh` — optional startup script
- `workspace/` — host-mounted ROS workspace (src/, build/, install/)
- `.devenv/` — auto-generated by `docker-env up/build`
- `.claude_local/` — auto-generated, per-project Claude Code data

### Docker Conventions

All containers use: `network_mode: host` (ROS DDS discovery), `privileged: true`, `command: tail -f /dev/null` (keep-alive, attach via exec), X11 forwarding via DISPLAY/XAUTHORITY. GPU projects use `runtime: nvidia`. SSH agent forwarding (`--mount=type=ssh`) is used for private repo clones during build. Git identity is inherited from host via `~/.gitconfig` include.

## Key Files

- `.bin/docker-env` — main CLI (bash)
- `.bin/autocomplete_docker_dev_setup` — bash completion
- `.dev_env_image/extend_docker_compose.py` — compose merger (Python), resolves `$PROJECT_DIR`/`$PROJECT_NAME`
- `.dev_env_image/devenv.Dockerfile` — shared dev layer
- `.dev_env_image/devenv_compose.yml` — dev overlay template
- `.dev_env_image/complementary_bashrc` — shell functions available inside containers (`rosbuild`)

## Adding a New Project

Create a directory with a `Dockerfile` and `docker-compose.yml` (single service with `container_name`). The CLI auto-discovers any non-hidden top-level directory. The devenv layer is applied automatically on `docker-env up` or `docker-env build`. Whitelist any extra project files (beyond Dockerfile, docker-compose.yml, entrypoint.sh) in `.gitignore`.
